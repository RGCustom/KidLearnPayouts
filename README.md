# Мотиватор (KidLearnPayouts) 2.0

Семейный учёт по «Договору» между родителями и ребёнком: накопления за домашку, дела и оценки, штрафы, выплаты,
статистика и сам договор для печати. Тёмный веб-интерфейс, удобный на телефоне. Один экземпляр — одна семья,
в нём сколько угодно детей, у каждого свои баланс, записи, выплаты, тарифы, категории дел и договор.

## Возможности
- **Три роли.**
  - **Администратор:** всё — аккаунты, дети, тарифы, договор, выплаты, удаление, ссылки и PIN детей, журнал.
  - **Взрослый:** смотрит и добавляет записи, удаляет и отменяет только свои. Тарифы и аккаунты недоступны.
    Выплаты — только если администратор включил это на аккаунте. Доступ можно ограничить конкретными детьми.
  - **Ребёнок:** без логина и пароля, по секретной ссылке (и PIN, если включён). Видит только своё и ничего не меняет.
- **Дети.** Общий обзор, переключатель, порядок, архив (удалить ребёнка нельзя — деньги и история сохраняются).
- **Деньги.** Категории дел (в том числе штрафные и «раз в день»), оценки и контрольные по шкале, которую вы задаёте
  для каждого ребёнка, свои записи ±, выплата с частичным остатком, отмена и удаление невыплаченных записей.
- **Договор.** Свой у каждого ребёнка, с редакциями: действующая, будущие и архив. Шкала, день выплаты и пример берутся
  из настроек, раздел «Правила игры» редактируется. Внизу пометка, что это игровой семейный документ.
- **Безопасность.** Серверные сессии, «Запомнить меня», защита от перебора паролей и PIN, отзыв устройств, журнал действий.

## Установка на Unraid
1. Дождитесь зелёной галочки в **Actions** (образ собирается автоматически при каждом коммите в `main`).
2. В терминале Unraid скачайте шаблон:
   ```
   wget -O /boot/config/plugins/dockerMan/templates-user/my-KidLearnPayouts.xml \
     https://raw.githubusercontent.com/RGCustom/KidLearnPayouts/main/kidlearnpayouts.xml
   ```
3. **Docker → Add Container →** выберите шаблон **KidLearnPayouts**. Задайте **пароль администратора**
   (`ADMIN_PASSWORD`), проверьте часовой пояс (`TZ`) и порт → **Apply**.
4. Откройте `http://IP-сервера:8090` и войдите: логин **`admin`**, пароль — тот, что задали.
5. Дальше всё делается в самом приложении: **Дети** (добавить ребёнка, настроить доступ), **Аккаунты** (взрослые),
   **Тарифы** и **Договор** у каждого ребёнка.

Обновление: после нового коммита дождитесь Actions, затем на вкладке Docker → *Check for updates* / *Force update*.
Если Unraid пишет «pull access denied» — откройте Packages в профиле GitHub → `kidlearnpayouts` →
*Package settings* → *Change visibility* → **Public**.

### Docker Compose
Готовый файл — `docker-compose.yml` (для плагина «Docker Compose Manager» или любого `docker compose`). Минимум —
задать `ADMIN_PASSWORD` и путь к данным.

### Без GitHub Actions (сборка прямо на сервере)
```
docker build -t kidlearnpayouts:latest https://github.com/RGCustom/KidLearnPayouts.git#main
```
и в шаблоне замените Repository на `kidlearnpayouts:latest`.

## Обновление с версии 1.7
Ничего делать вручную не нужно: обновите образ и запустите контейнер. При первом запуске:
1. рядом с базой появляется резервная копия `uchet.db.bak-v1.7-<дата-время>` (в папке данных);
2. база переносится на новую структуру **одной транзакцией**, после чего сверяются число записей, суммы, накопление
   и выплаты. Если что-то не сходится или произошла ошибка — всё откатывается, в лог выводится причина, контейнер
   останавливается, а база остаётся такой, как была (смотрите лог контейнера);
3. из `tariffs.json` создаётся первый ребёнок (имя, тарифы оценок и контрольных, категории, лимит «вне очереди»),
   все записи и выплаты привязываются к нему, а категории, которых уже нет в тарифах, остаются в истории как
   «… (удалена)»; из данных договора создаются первый договор и его редакция № 1;
4. из `ADMIN_PASSWORD` создаётся администратор.

Что изменится для вас: **вход теперь по логину и паролю** (логин `admin`, пароль прежний), открытого просмотра больше нет,
сессии придётся открыть заново. `tariffs.json` остаётся на диске как резерв и больше не читается.

**Откат на 1.7:** остановите контейнер, удалите `uchet.db`, `uchet.db-wal`, `uchet.db-shm`, скопируйте
`uchet.db.bak-v1.7-…` под именем `uchet.db` и верните образ версии 1.7. Всё, что внесено уже в версии 2.0, в копию
не попадёт.

## Роли и права
| | Администратор | Взрослый | Ребёнок |
|---|---|---|---|
| Смотреть баланс, историю, статистику, договор | да (все дети) | да (назначенные дети) | только своё |
| Добавлять записи | да | да | нет |
| Удалять и отменять записи | любые невыплаченные | только свои невыплаченные | нет |
| Отмечать выплаты | да | если включено на аккаунте | нет |
| Тарифы, категории, шкала | да | нет | только смотреть |
| Договор: правка и редакции | да | нет | только смотреть |
| Аккаунты, дети, доступ детей, журнал | да | нет | нет |

Записи из версии 1.7 не имеют автора, поэтому удалить их может только администратор. Аккаунты не удаляются, а
отключаются (так сохраняется авторство записей и журнал). Свой пароль каждый меняет в **Мой аккаунт**; временный
пароль нового аккаунта нужно сменить при первом входе. Сброс пароля делает администратор.

## Доступ ребёнка (ссылка и PIN)
В **Дети → настроить** у каждого ребёнка выберите режим:
- **Выкл** — ссылка не работает;
- **Ссылка** — ребёнок открывает свою ссылку (удобно держать в закладке, сессия 30 дней со скользящим продлением);
- **Ссылка + PIN** — дополнительно вводит PIN (4–8 цифр, лучше 6). Сессия 12 часов, а с галочкой «запомнить это
  устройство» — как «Запомнить меня».

На странице доступа есть ссылка с кнопкой «Копировать» и QR-код. Токен ссылки хранится открыто (чтобы вы всегда могли
снова открыть ссылку и QR), PIN — только хэшем. После 5 неверных PIN вход закрывается на 5 минут (счёт для каждого
ребёнка отдельно; администратор может снять блокировку). **Создать новую ссылку** отключает старую и все устройства ребёнка;
то же делают смена режима, смена PIN и архивация ребёнка. Список устройств ребёнка можно просмотреть и отозвать.

Ссылка открывает личные данные ребёнка — передавайте её только ему. Предпросмотр ссылки в мессенджерах вход не создаёт.

## Договор
Страница **Договор** показывает **действующую редакцию**. Изменения тарифов, шкалы, данных договора и правил попадают
в неё только после кнопки **«Создать редакцию»** (с датой «действует с»); старые редакции не меняются и открываются из
списка. Редакция с будущей датой «вступит в силу». Администратор видит баннер, если настройки отличаются от последней
редакции, и может открыть черновик. Данные договора, подписанты и «Правила игры» правятся в **Договор → Править**.

В «Правилах игры» пустая строка — новый абзац, строка «- …» — пункт списка; HTML не поддерживается и экранируется.
Печать и PDF — кнопка на странице («Печать → Сохранить как PDF»).

## Журнал
**Меню пользователя → Журнал** (администратор): входы и ошибки входа, блокировки, действия с аккаунтами, детьми, доступом,
договором, тарифами, а также все записи, выплаты, удаления и отмены с суммой и автором. Есть фильтры по ребёнку, кто,
действию и периоду. Паролей, PIN и токенов в журнале нет. Записи старше `AUDIT_KEEP_DAYS` дней удаляются.

## Настройки (переменные окружения)
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADMIN_PASSWORD` | — | Пароль первого администратора (логин `admin`). Используется **только если администратора ещё нет**; дальше пароль не перезаписывается. |
| `RESET_ADMIN_PASSWORD` | `0` | `1` вместе с `ADMIN_PASSWORD` — один раз сбросить пароль администратора (и отключить его сессии). Уберите после входа. |
| `TZ` | `Europe/Moscow` | Часовой пояс: влияет на «сегодня» и день выплаты. |
| `SESSION_HOURS` | `12` | Срок входа без «Запомнить меня» (скользящий). |
| `REMEMBER_DAYS` | `30` | Срок с «Запомнить меня» (скользящий), допустимо 30–90. |
| `COOKIE_SECURE` | `0` | `1` — если заходите по HTTPS. |
| `TRUST_PROXY` | `0` | `1` — если перед контейнером стоит reverse proxy (NPM, Caddy, Traefik). |
| `BASE_URL` | — | Внешний адрес для ссылок и QR детей, например `https://kids.example.com`. Если пусто — адрес, по которому открыта страница. |
| `AUDIT_KEEP_DAYS` | `365` | Сколько хранить журнал; `0` — не удалять. |
| `PORT` | `8080` | Порт внутри контейнера. |
| `CONFIG_DIR` | `/config` | Папка данных внутри контейнера. |
| `PUID` / `PGID` | `99` / `100` | Права на папку данных (как у контейнеров Unraid). |

## HTTPS и reverse proxy
Без HTTPS в интернет не открывайте: логины, PIN и ссылки детей можно перехватить. Используйте reverse proxy или VPN и
включите `TRUST_PROXY=1`, `COOKIE_SECURE=1`, задайте `BASE_URL`. **Обязательно `TRUST_PROXY=1` за прокси:** иначе все
запросы приходят с адреса прокси, и пять неверных паролей подряд закроют вход всем на 5 минут.

Токен ссылки ребёнка попадает в адрес первого запроса, а значит в журналы reverse proxy — берегите к ним доступ.

## Данные и резервные копии
Папка данных (`/mnt/user/appdata/kidlearnpayouts/`):
- `uchet.db` — вся база (записи, выплаты, аккаунты, договоры, журнал). Резервная копия — остановить контейнер и скопировать
  файл (вместе с `uchet.db-wal` и `uchet.db-shm`, если они есть);
- `secret.key` — ключ подписи cookie с защитным токеном форм;
- `uchet.db.bak-v1.7-…` — копия, сделанная при обновлении с 1.7;
- `tariffs.json` — только у обновившихся с 1.7, не читается.

## Безопасность в двух словах
Пароли и PIN хранятся хэшем; в cookie — случайный токен, в базе его хэш; все изменяющие запросы защищены CSRF-токеном;
перебор паролей и PIN ограничен и считается в базе; страницы ребёнка доступны только по его сессии, взрослые и дети
друг друга не подменяют; весь вывод экранируется, скрипты только из собственных файлов (строгий CSP).
Без входа открыты только страница входа, `/healthz`, статические файлы, манифест и иконки.

## Для разработчиков
- Структура: `app.py` в корне, шаблоны в `templates/`, стили и скрипты в `static/`, тесты в `tests/`.
- Тесты: `pip install -r requirements.txt && python tests/test_migration.py` (миграция с v1.7, роли, сессии, дети, доступ
  ребёнка, договор, журнал). В образ папка `tests/` не попадает.
- **Иконки.** Приложение ждёт `static/icons/apple-touch-icon.png`, `favicon-32.png`, `icon-192.png` и `icon-512.png`
  (для «На экран Домой»). Файлы лежат в репозитории — не удаляйте папку `static/icons/`.
- Схема базы версионируется в таблице `meta` (`schema_version`); база, созданная более новой версией приложения,
  не открывается.

## Что нового в 2.0
